# Research Synthesis — Experiment E4 (Concurrency & HTTP 429 Analysis)

## 1. Context & Purpose

Experiment **E4** investigated connection concurrency ($N=1, 4, 8, 16$) and rate-limiting responses during sustained measurement tests.

## 2. Empirical Findings

1. **Concurrency Impact**:
   - Single-connection TCP streams ($N=1$) frequently bottleneck below link capability due to TCP receive window caps and packet loss recovery delays.
   - Multi-stream testing ($N=4 \dots 8$) saturates link capacity reliably.
2. **HTTP 429 Rate Limiting**:
   - High-frequency parallel HTTP requests occasionally hit edge server rate limits, returning HTTP status code 429 (Too Many Requests).

## 3. CRITICAL Requirements Enforced in IPMCAS

1. **Explicit HTTP 429 Classification**:
   - An HTTP 429 response must **NEVER** be recorded as 0 Mbps or as a physical network failure.
   - The engine explicitly tags the result status as `SERVER_RATE_LIMITED`.
2. **Detailed Request Telemetry**:
   - The engine logs:
     - `concurrency_level` ($N$)
     - `http_status_code` (429, 200, 503, etc.)
     - `successful_requests_count`
     - `failed_requests_count`
     - `rate_limited_requests_count`
